# Foundation data and dependencies

The foundation units F01-F13 use small synthetic tables and a pinned Python
stack. This page is the student-facing reference for both. The repository files
themselves live outside the documentation site; the paths below are exact.

## Foundation synthetic datasets {#foundation-datasets}

All four tables are generated by a documented Python script. They contain no real
people, no scraped text, and no personal data. The course releases the generated
tables under **CC0-1.0**, so you may copy, modify, and redistribute them.

| Dataset | Rows | Columns | Target | Used in |
| --- | --- | --- | --- | --- |
| `house_prices.csv` | 600 | 7 | `sale_price` | F05, F06, F08 |
| `student_performance.csv` | 500 | 8 | `passed`, `final_score` | F03, F08, F09, F10 |
| `student_performance_messy.csv` | 510 | 7 | `passed` | F04 lab |
| `customer_segments.csv` | 420 | 5 | none; `latent_segment` is withheld from clustering | F07 |

Notes that matter for honest reporting:

- `student_performance_messy.csv` has 510 rows because 10 duplicate rows were
  appended to 500 unique enrollments. Deduplication returns 500 rows.
- The F04 guided notebook builds its own 328-row messy table with seed `7`. Its
  counts (328 raw, 320 after deduplication) do not describe the external CSV.
- `customer_segments.csv` includes `latent_segment` only so you can score
  clustering after the fact. Never use it as an input feature.
- The tables are deliberately simple: mostly additive relationships with
  controlled noise. They are suitable for learning workflows, not for claims
  about real housing markets, students, or customers.

### Provenance and privacy

| Field | Value |
| --- | --- |
| Source | `scripts/make_foundation_data.py` in this repository |
| License | CC0-1.0 |
| Version | Determined by the generator and the seed you pass |
| Personal data | None |
| Checksum | SHA-256 values are written to `manifest.json` beside the CSVs |

The student table is not a measurement of any real course. Do not use it to make
decisions about people, and do not present a result on it as evidence about real
students.

## Generating the data {#data-generator}

Run the generator from the repository root:

```bash
python scripts/make_foundation_data.py
```

The default output directory is `datasets/foundations/generated/`. To choose a
different seed or location:

```bash
python scripts/make_foundation_data.py --out-dir datasets/foundations/generated --seed 42
```

The command writes four CSV files and a `manifest.json` containing the row count,
column count, and SHA-256 of each file. Record the seed and the checksum in your
lab report. Generated data is excluded by `.gitignore`; regenerate it instead of
committing it.

## CPU and GPU requirements {#cpu-and-gpu-requirements}

Install one dependency set from the repository root. The files are small and
intentionally non-overlapping.

| File | Adds | Use it for |
| --- | --- | --- |
| `requirements/base.txt` | NumPy, pandas, scikit-learn, matplotlib, joblib | Classical machine learning, no notebook server |
| `requirements/notebooks.txt` | `base.txt` plus JupyterLab, ipykernel, nbclient | Running the guided notebooks |
| `requirements/cpu.txt` | `notebooks.txt` plus CPU-only PyTorch | The complete foundation sequence, including F11-F13 |
| `requirements/gpu.txt` | `notebooks.txt` plus a PyTorch version range | Optional CUDA path; install the matching wheel yourself |
| `requirements/docs.txt` | MkDocs and Material for MkDocs | Building this site only |

CPU setup:

```powershell
python -m pip install -r requirements/cpu.txt
```

GPU setup is a two-step, opt-in process. Read `requirements/gpu.txt` first and
confirm that you own the machine and have a matching NVIDIA driver. Then install
the CUDA wheel recommended by the official PyTorch selector for your driver. Do
not install a GPU stack on a CPU-only machine or on shared hardware without
permission.

The verified authoring environment for F01-F13 was Windows 11, Python 3.12.10,
CPU-only, with PyTorch 2.4.1+cpu. No GPU or Google Colab run was executed while
authoring these units. The notebooks detect CUDA at runtime and fall back to CPU,
so every core exercise completes without a GPU. Record your own device and
versions rather than copying the authoring environment.
