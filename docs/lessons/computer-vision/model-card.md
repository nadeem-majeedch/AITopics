# Model card and dataset card templates {#model-card}

**Section path:** [Overview](index.md) · Module [CV14](cv14-evaluation-robustness-deployment.md) · **Template**

A model is not finished when it trains. It is finished when someone else can see what it
does, what it does not do, and how you know. That document is the model card.

The templates live in `projects/computer-vision/vision_core/cards.py` and are checked by
code, so an incomplete card fails rather than being politely ignored.

## Generate one

```python
from vision_core import cards

text = cards.render(
    cards.MODEL_CARD_TEMPLATE,
    model_name="object-classifier-v1",
    version="1.0",
    date="2026-11-01",
    author="your name",
    architecture="TinyCNN, 72,499 parameters, 32x32 RGB input",
    parameters="72,499",
    input_spec="32x32 RGB uint8, normalized with train-split mean/std",
    output_spec="4 class probabilities: bottle, mug, ball, book",
    intended_use="Sorting a fixed set of four object categories in good lighting",
    out_of_scope="People, vehicles, text, medical images; any safety-critical decision",
    metrics_table=cards.metrics_table(rows),
    failure_modes="square/book confusion at low contrast; occluded objects",
    limitations="18 test images; synthetic data; no real-camera evaluation",
    licence="Data CC0-1.0; original weights follow the repository code licence; weights derived from third-party pretrained models keep their upstream terms",
    reproduce_command="python lab4_finetune_objects.py --epochs 12",
)
open("model_card.md", "w").write(text)
```

Unfilled placeholders remain visible (`{{intended_use}}`), which is deliberate: a card
with a blank field looks unfinished because it is.

```python
cards.check_card("model_card.md")
# {'complete': True, 'missing': []}
```

Lab 4's verified run writes `outputs/lab4_model_card.md` with `complete=True`.

## The template

```markdown
# Model card: {{model_name}}

| Field | Value |
| --- | --- |
| Version | {{version}} |
| Date | {{date}} |
| Author / owner | {{author}} |
| Architecture | {{architecture}} |
| Parameters | {{parameters}} |

## Intended use

{{intended_use}}

## Out of scope

{{out_of_scope}}

## Inputs and outputs

- Input: {{input_spec}}
- Output: {{output_spec}}

## Training data

Source, licence, size, split rule, and known gaps.

## Metrics

{{metrics_table}}

Every metric states its dataset, sample size, and threshold. A number without those three
is not a result.

## Known failure modes

{{failure_modes}}

## Limitations

{{limitations}}

## Ethical and legal considerations

Consent, personal data, demographic performance, and prohibited uses.

## Reproduction

```bash
{{reproduce_command}}
```

## Contact

Who to ask, which commit, which issue tracker.
```

## What "complete" means, field by field

| Field | Weak | Strong |
| --- | --- | --- |
| Intended use | "image classification" | "four-category object sorting on a fixed camera, indoor lighting" |
| Out of scope | "not for everything" | "no people, no safety decisions, no images below 200 lux" |
| Metrics | "accuracy 95%" | "accuracy 0.500 on 18 held-out images, threshold 0.5, chance 0.25" |
| Failure modes | "some errors" | "square/book confusion at low contrast; measured 2/18" |
| Limitations | "small dataset" | "synthetic only; no real-camera data; 18 test images" |

## Dataset card

The companion document, generated by `scripts/make_vision_data.py` as
`data/dataset_card.json`:

```markdown
# Dataset card: {{name}}

| Field | Value |
| --- | --- |
| Version / date | {{version}} |
| Licence | {{licence}}            <!-- SPDX id, e.g. CC0-1.0 -->
| Attribution | {{attribution}}    <!-- exactly as the licence requires -->
| Source | {{source}}             <!-- URL, generator, or collection method -->
| Size | {{size}}                   <!-- images, sources, classes, splits -->
| Collection method | {{collection}}  <!-- how images were produced or gathered -->
| Annotations | {{annotations}}    <!-- format, tool, annotator count, agreement -->
| Split rule | {{split}}            <!-- grouped by what, and why -->
| Known gaps | {{gaps}}               <!-- missing conditions, classes, groups -->
| Redistribution | {{redistribution}} <!-- may others reuse it, and how -->
```

For this section's generated data: `licence: CC0-1.0`, `source: synthetic renderer in
scripts/make_vision_data.py`, `split: grouped by source_id`, and `gaps: no real-world
lighting, pose, or camera variation`.

## Why this is graded

A card is the only artifact that survives the project. Six months later nobody remembers
which split produced 0.933, whether the boxes were audited, or which threshold the product
used. The card is the answer to "can we trust this?" - and writing it is how you discover
which of your own claims you cannot support.

## Checklist before you submit a card

- [ ] Every `{{placeholder}}` replaced, or the field explicitly marked "not evaluated"
- [ ] Every metric has dataset, N, and threshold
- [ ] At least three measured failure modes, not adjectives
- [ ] Out-of-scope section names uses you would refuse
- [ ] Licence and attribution for data, and for any pretrained weights
- [ ] Reproduction command actually reproduces the reported number
- [ ] `cards.check_card` returns `complete=True`
