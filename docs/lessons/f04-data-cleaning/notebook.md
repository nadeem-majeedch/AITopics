# F04 guided notebook

**Module path:** [Lesson](index.md) · **Guided notebook** · [Lab brief](lab.md) · [Assessment](assessment.md)

**Notebook file:** `notebooks/foundations/f04_data_cleaning.ipynb`  
**Hardware:** CPU-only; pandas and scikit-learn  
**Time:** 3-4 hours including reading the explanations

The notebook builds a deliberately messy 328-row table with seed `7`, then cleans
it. Every problem it fixes was injected on purpose, so the counts in the outputs
are known in advance and the assertions can be exact.

## What the notebook does

| Section | What you do | Evidence produced |
| --- | --- | --- |
| 1. Inspect before cleaning | Print shape, missing counts, duplicates, and raw category values | `shape: (328, 7)`; missing `26 / 19 / 34`; `duplicate rows: 8`; four raw spellings |
| 2. Remove duplicates and normalize labels | `drop_duplicates`, then strip, lowercase, map, and bucket to `Unknown` | 320 rows; a controlled value set for `course` and `tutoring` |
| 3. Numeric imputation | Build numeric and categorical pipelines plus a `ColumnTransformer` | A printed pipeline object with impute, scale, and encode steps |
| 4. Compare dropping rows with imputation | Score both strategies on the same 5 stratified folds | Imputed `0.791` over 320 rows; complete-case `0.770` over 248 rows |
| 5. Fit the final preprocessing | `fit_transform` on the cleaned table, then save | `transformed shape: (320, 9)`; `outputs/students_clean.csv` |
| Common decisions | Read the trade-off table | Your own cleaning specification |

The notebook asserts that missing values and duplicates exist before cleaning, and
that the row count falls after deduplication. Those assertions guard against the
most embarrassing failure: cleaning a table that was never dirty and concluding
the pipeline works.

## Troubleshooting

| Symptom | Diagnosis | Fix |
| --- | --- | --- |
| `sparse_output` keyword error | scikit-learn older than 1.2 | Upgrade scikit-learn; do not edit the encoder arguments |
| `KeyError` naming a column in `ColumnTransformer` | Column list does not match the frame after cleaning | Print `list(clean.columns)` and compare with `numeric_columns` and `categorical_columns` |
| `AssertionError` on `len(clean) < len(df)` | `drop_duplicates` ran on an already deduplicated frame | Restart the kernel and run all cells; do not rerun cells out of order |
| `ConvergenceWarning` from `LogisticRegression` | Solver did not converge in the default iterations | The notebook sets `max_iter=2000`; if it persists, report it rather than ignoring it |
| Transformed shape is `(320, 10)` | An `Unknown` category appeared | Check `clean["course"].value_counts()`; document the extra column |
| `SettingWithCopyWarning` | Assignment on a slice of a slice | Assign on `clean` with `.loc`, or start from `df.drop_duplicates().copy()` |
| `ValueError: Input contains NaN` at fit time | A numeric column was left out of the numeric pipeline | Confirm every numeric column appears in `numeric_columns` |
| CV score is much higher than `0.791` | Preprocessing was fit before the split | Keep the pipeline inside `cross_val_score`; do not pre-transform `X` |
| `FileNotFoundError` writing the CSV | Working directory is not where you expect | Print `Path.cwd()`; the first cell creates `outputs/` there |

If a fold score differs by more than a few thousandths from the verified run,
check the scikit-learn version before checking your code.
