## Objectives

1. Build a two-headed classifier: garment **category** and garment **colour**.
2. Report per-class precision, recall, and F1 on a clean test set, plus the confusion matrix.
3. Measure robustness with a one-factor-at-a-time sweep and explain which head degrades first.
4. State, structurally, what the model cannot output - and why that is a design requirement
   rather than a disclaimer.

## Prerequisites

- Data: generated by `synth.garment_dataset` at run time (no downloads, no real photographs).
- 240 training images (seed 3), 60 test images (seed 107) - disjoint seeds.
- Label set: `shirt`, `trousers`, `jacket`, `hat`; `red`, `blue`, `green`, `black`, `white`,
  `yellow`.

!!! warning "Scope, stated before the numbers"
    The model answers two observable questions about a garment. It has **no** output for gender,
    age, ethnicity, body shape, health, mood, or identity, and no code path that could produce
    one. Predicting sensitive attributes from appearance is unreliable and unlawful for many
    purposes (GDPR Art. 9 and equivalents). If a task appears to need it, the task needs
    redesigning. See [VD10](../vd10-clothing-and-appearance.md) and
    [VD15](../vd15-responsible-video-analytics.md).

### 2. Read the clean table, then distrust it

```
clean test set
  category : accuracy 1.000   macro F1 1.000
  colour   : accuracy 1.000   macro F1 1.000
```

A perfect score on balanced synthetic data means "the task is solvable", not "the model is
good". Write that sentence down before you look at the sweep; it is the difference between a
report and a demo.

### 3. Read the sweep

| Condition | category acc | colour acc |
| --- | --- | --- |
| clean | 1.000 | 1.000 |
| brightness x0.7 | 0.867 | 0.883 |
| brightness x0.45 | 0.533 | 0.133 |
| occlusion 30% | 0.550 | 0.717 |
| occlusion 55% | 0.433 | 0.183 |
| background 40% | 0.433 | 0.967 |
| dark + occlusion | 0.417 | 0.133 |

Two conclusions to defend:

1. **Colour is a brightness measurement.** At 45% brightness it collapses to 0.133, below what a
   six-class guess would score in the worst case and clearly no longer usable.
2. **Category survives better** because shape is more invariant than colour - but it still falls
   to 0.433 when the background changes, which means the trunk learned context as a shortcut.

## Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| Category accuracy stuck near 0.25 | learning rate too low or too few epochs | use defaults; 25 epochs is enough here |
| Colour accuracy 1.0 but category low | category needs shape cues that 48x48 limits | raise `--per-class`, more epochs |
| Sweep identical to clean | model not in eval mode | `predict_garments` sets `eval()`; check you used it |
| Grid image missing | `outputs/` not writable | check permissions; the lab reports the failure |
| Wants to add a third head | out of scope | redesign the task, not the model |

## Extensions

1. **Colour constancy.** Normalise each image by its own channel means before inference and
   re-run the sweep. Report the recovered accuracy at 0.45 brightness.
2. **Grayscale ablation.** Train with images converted to grayscale (category only). How much
   category accuracy survives? This isolates shape from colour.
3. **Per-track voting.** Apply the model to several crops of the same synthetic garment with
   different perturbations and majority-vote the attribute. Report stability.
4. **Licensed data.** Swap in a licensed clothing dataset (e.g. DeepFashion, for which you must
   check the licence and terms yourself) and write the data card entries that change: provenance,
   consent, retention, and whether any person is identifiable.
5. **Calibration.** Report the model's confidence distribution on clean vs dim images. Does the
   model know it is struggling?
