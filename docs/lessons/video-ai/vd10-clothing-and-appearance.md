## Why this module exists

Appearance attributes - "a person in a red jacket" - are the feature that makes video search
possible and the feature that turns a harmless camera into a surveillance instrument. This
module teaches the technical version and states the boundary in the same breath, because in
this domain the boundary is part of the engineering.

## The label set is the design decision

The section models **garment category** and **garment colour**, nothing else:

| Head | Classes |
| --- | --- |
| category | `shirt`, `trousers`, `jacket`, `hat` |
| colour | `red`, `blue`, `green`, `black`, `white`, `yellow` |

Explicitly not modelled: gender, age, ethnicity, body shape, health, mood, identity.

That is not modesty; it is accuracy. Sensitive attributes inferred from appearance are
**guesses with a confidence score attached**, and the measured error rates for such inference
are high enough that using them for decisions is both unreliable and, in many jurisdictions,
unlawful (GDPR Art. 9 and equivalents). A model that cannot output a value cannot leak it,
cannot be repurposed for it, and cannot be evaluated as if it were measuring something.

```python
from video_core.garments import sensitive_attribute_statement
print(sensitive_attribute_statement())
```

The lab prints this next to the results, on the same screen, every time it runs. If a project
appears to need a sensitive attribute, the task needs redesigning.

## The data

240 training images and 60 test images, 48x48 RGB, generated by `synth.garment_dataset` from
disjoint seeds (3 for train, 107 for test), balanced by construction:

```
train: 240 images, seed 3
test :  60 images, seed 107   (disjoint seeds -> no shared random draw)
balance: per-category [60, 60, 60, 60], per-colour [40, 40, 40, 40, 40, 40]
```

Two properties worth noting because they are what a real project rarely has:

- **Disjoint seeds.** The discrete analogue of splitting by video: no test image is a near-copy
  of a training image, so the score measures generalisation within the generator's distribution.
- **Balance.** Accuracy is not inflated by class prior, and macro F1 equals accuracy - which
  makes the two metrics agree and removes a common source of confusion.

The images are synthetic shapes on synthetic backgrounds, CC0, with no people. That is a real
limitation and it is stated in the dataset card: this model has never seen a photograph.

## Two heads, one trunk

```python
from video_core.garments import GarmentNet, predict_garments

model = GarmentNet(num_categories=4, num_colours=6)   # 24,458 parameters
cat_pred, col_pred = predict_garments(model, images)
```

One convolutional trunk, two linear heads. The alternative - two independent models - doubles
the compute and learns the same edges twice. The trade-off: a shared trunk means the two tasks
compete for capacity, and a class that is visually entangled across heads (a "black jacket"
pattern that only appears with black) can bias both.

Training is 25 epochs, batch 64, Adam at 2e-3 (the lab passes `epochs=25`; the function's
default is 14), and reaches a training loss of 2.80 → 0.155 in under a minute on one CPU
thread. The loss is the sum of the two cross-entropies, so it is not comparable to a
single-head number.

## Results: perfect on the clean set, and why that is not the headline

```
clean test set
  category : accuracy 1.000   macro F1 1.000
  colour   : accuracy 1.000   macro F1 1.000
```

A perfect score on a synthetic, balanced, well-lit test set means the task is solvable, not that
the model is good. The headline is the sweep:

| Condition | category acc | colour acc |
| --- | --- | --- |
| clean | 1.000 | 1.000 |
| brightness x0.7 | 0.867 | 0.883 |
| brightness x0.45 | 0.533 | **0.133** |
| occlusion 30% | 0.550 | 0.717 |
| occlusion 55% | 0.433 | 0.183 |
| background 40% | 0.433 | 0.967 |
| dark + occlusion | 0.417 | **0.133** |

Read the two columns against each other:

- **Colour is a brightness measurement.** Push it to 45% brightness and accuracy falls from
  1.000 to 0.133 - below chance for six classes (0.167) would be possible; here it is essentially
  "always guess black". Colour constancy is the missing piece: the model learned RGB values,
  not "redness relative to the scene".
- **Category is a shape measurement**, and it degrades more gracefully: 0.533 at the same
  brightness, 0.433 under heavy occlusion.
- **Background variation costs category a lot** (0.433) - the trunk has learned context as a
  shortcut, which is the classic synthetic-data failure.

The engineering conclusion is specific: **if a project needs colour, it needs colour
correction before the classifier, not a bigger classifier after it.** A white-balance step or
per-image normalisation would recover much of that 0.13 at a cost of microseconds.

## The sweep is the deliverable

```python
from video_core.garments import perturb, robustness_sweep

images = perturb(clean, brightness=0.45)        # deterministic given a seed
report = robustness_sweep(model, images, categories, colours)
```

`perturb` handles brightness, occlusion (a black rectangle at a seeded position), and background
swaps, all bounded to [0, 1]. `robustness_sweep` runs the same test set through each condition
and returns accuracy per head - the table above, reproducible.

One factor at a time is a deliberate simplification. Real footage combines factors, which is why
the sweep includes a `dark_plus_occlusion` row: it is the only combined condition, and it is the
worst one (0.417 / 0.133). Use it as a reminder that one-at-a-time robustness is an upper bound.

## Where this sits in a video pipeline

Attributes are usually applied to **crops from a tracker**, not to whole frames:

```python
# per confirmed track, once, on the best-scoring crop
crop = frame[y1:y2, x1:x2]
category, colour = predict_garments(model, as_float01(crop)[None])
```

Three consequences:

- The crop resolution is whatever the detector produced - a distant vehicle gives a 20x20 crop
  and the attribute model's accuracy on it is far below the table above.
- The attribute is per *track*, so one vote across frames is possible and much more stable than
  per frame. This is the same argument as Lab 6's clip vote.
- Small crops are exactly where the brightness failure bites, because a night scene's crop is
  both small and dark.

## Responsible scope, concretely

| Do | Do not |
| --- | --- |
| Model garment category and colour | Model gender, age, ethnicity, health, identity |
| Search your own footage with consent | Build a person-finding system for others |
| State the crop size and the lighting conditions | Quote a clean-set accuracy for a night deployment |
| Delete crops after the query | Retain appearance descriptors indefinitely |
| Publish aggregate counts | Publish per-person appearance histories |
