# Model card - Video AI traffic analytics {#model-card}

**Section path:** [Overview](index.md) · [Responsible use](vd15-responsible-video-analytics.md) · [Governance](governance.md) · **Model card**

Two cards follow: the section's own system, then a template for your capstone. A card is a
one-page answer to "what is this, what does it do, and what must it not be used for". The last of
those three is the one reviewers read.

---

## Part 1: the section's system

### Overview

| Field | Value |
| --- | --- |
| Name | Video AI traffic analytics (teaching reference) |
| Version | 1.0, matching `projects/video-ai` |
| Type | Per-frame object detection + IoU tracking + geometric line counting |
| Task | Count vehicles crossing a line, by class and direction |
| Temporal model | **none** in the counting pipeline; the tracker supplies identity over time |
| Licence | AITopics code MIT; educational content CC BY 4.0; synthetic data CC0 1.0 (provenance verified); SSDLite weights unresolved (torchvision code is BSD-3-Clause; no separate weight licence stated) |

The SSDLite checkpoint is downloaded at runtime and is not redistributed with this
repository. Torchvision states that pretrained models may have their own licences
or terms derived from the training dataset; the COCO weights therefore remain
unresolved here, and a redistributed or fine-tuned checkpoint needs its own review.

### Intended use

- Teaching detection, tracking, counting, and evaluation on synthetic footage.
- A reference implementation to compare against your own.
- Benchmarking sampling strategies, thresholds, and tracker parameters.

### Out of scope

- Identifying, re-identifying, or tracking people.
- Inferring protected attributes (gender, age, ethnicity, health) from appearance.
- Enforcement, ticketing, or any decision affecting an individual.
- Night, rain, or dense-congestion operation without new data and re-measurement.
- Number-plate reading, face recognition, cross-camera identity linkage.

### Components and sizes

| Component | Parameters | Role | Honest description |
| --- | --- | --- | --- |
| `TinyDetector` | 138,579 | per-frame vehicle detection | trained from scratch on this section's train frames |
| `SSDLiteDetector` | 3,440,060 | baseline | COCO-pretrained, applied per frame, not adapted |
| `TrafficSSDLite` | 3,440,060 | adapted detector | frame-level fine-tune of the above (404 tensors transferred) |
| `IoUTracker` | 0 | identity over time | IoU + Hungarian + velocity prediction |
| `LineCounter` | 0 | crossings | geometric side test, once per track |
| `GarmentNet` | 24,458 | category + colour | two heads only, no identity output |
| `TemporalClassifier` | 48,805 | clip classification | CNN + GRU, trained from scratch (Lab 6) |

### Data

| Field | Value |
| --- | --- |
| Source | generated by `projects/video-ai/scripts/make_video_data.py` (`video_core.synth`), deterministic |
| Content | 7 clips, 60 frames each, 640x360, 10 fps; 4 vehicle classes; day/dusk/night/rain/shake/crowd |
| Labels | frame-exact boxes, track IDs, crossing events; no person labels |
| Splits | train `street_day`, `street_dusk`; val `street_quiet`; test `street_night`, `street_rain`, `street_shake`, `street_crowd` |
| Licence | CC0-1.0 |

### Metrics (measured, this repository)

| Task | Metric | Value | Split |
| --- | --- | --- | --- |
| Detection (scratch) | mAP@0.5 | 0.918 | `street_day` (in-domain) |
| Detection (COCO zero-shot) | mAP@0.5 | 0.048 day / 0.000 night | test-style clips |
| Detection (fine-tuned) | mAP@0.5 | 0.156 quiet / 0.033 night / 0.033 rain / 0.295 shake | held-out videos |
| Tracking | MOTA | 0.658 clean / -0.381 crowd / -0.019 shake | per scene |
| Tracking | ID switches | 5 clean / 8 crowd / 3 shake | per scene |
| Counting | total error | 0 clean / -3 crowd / -3 shake | per scene |
| Counting | per-cell error | 2 (class/direction attribution) | `street_day` |
| Attributes | macro F1 | 1.000 clean; 0.133 colour at 0.45 brightness | synthetic garment set |
| Action (temporal) | clip accuracy | 0.813 (frame baseline 0.507) | disjoint clips |
| Speed | ms/frame | 4.19 (TinyDetector) / 58.71 (SSDLite) | one CPU thread |

### Limitations

1. **Night and rain are effectively out of distribution**: recall 0.044 and 0.022 for the
   fine-tuned detector.
2. **Congestion breaks association**: more tracks than vehicles, and undercounting at the line.
3. **Camera motion breaks IoU association**: 3 of 6 crossings survive.
4. **Colour attributes are brightness measurements**: accuracy collapses in low light.
5. **All data is synthetic**: this system has never seen a photograph, let alone a real road.

### Ethical considerations

No identity output exists anywhere in the schema or the models, so the system cannot be
repurposed into person-level surveillance without a code change that would be visible in review.
Aggregates only; no retention of frames by default. See [governance](governance.md).

### Reproduction

```bash
python projects/video-ai/scripts/make_video_data.py
cd projects/video-ai
python lab3_tracking_and_counting.py
python lab8_performance.py
```

### What makes a card pass

| Criterion | Passes | Fails |
| --- | --- | --- |
| Out-of-scope section | specific, falsifiable | "for research only" |
| Metrics | sample size, split, and threshold | a bare number |
| Limitations | measured, with a number | "performance may vary" |
| Input unit | stated as frame or clip | "video AI" |
| Data | provenance and licence named | "public data" |

The card is marked as part of the capstone's 10%. A system with excellent numbers and a blank
"out of scope" section scores lower than a modest system that knows exactly what it must not be
used for.
